# 实验四 操作手册（部署 → 数据 → 压测 → 监控 → 统计）

本手册对应本组 5 台服务器，命令可直接复制。**密码不写在这里**：SSH 用各人自己的免密方式登录；数据库与应用的密码由脚本在服务器上随机生成，存放在 CDWY1 的 `/root/.config/lab4/`（权限 600）和 Docker secret 中。

## 0 服务器分工

| 指导书角色 | 本组服务器 | 私网地址 | 本实验中的内容 |
| --- | --- | --- | --- |
| A 编译 + JMeter | CDWY3 | 172.31.12.156 | JDK 21、Maven 3.9.16、JMeter 5.6.3（实验三已装好） |
| B MySQL | CDWY2 | 172.31.8.46 | 实验三的 `lab_mysql`（MySQL 9.2.0），新建库 `lab4_log` |
| C MongoDB 7.0 | CDWY5 | 172.31.13.151 | 本实验新加入 Swarm，`lab4_mongo`（mongo 7.0.48） |
| D Prometheus | CDWY4 | 172.31.1.19 | 实验三的 `lab_prometheus`，新增两个抓取任务 |
| E 两套日志服务 | CDWY1（Swarm manager） | 172.31.1.202 | `lab4_logjpa`（8081）、`lab4_logmongo`（8082） |

全部为 Ubuntu 18.04、2 核、约 1.8GB 可用内存、Docker 20.10.21。Swarm 管理命令只能在 CDWY1 上执行。

## 1 准备 CDWY5（只需做一次）

1. **安全组**：在华为云控制台把 CDWY5 加入与 CDWY1–4 相同的安全组（或放通来自 `172.31.0.0/16` 的流量）。否则 Swarm 端口 2377/7946/4789 和 MongoDB 27017 不通。
2. **安装与其他节点同版本的 Docker**（CDWY5）：

   ```bash
   apt-get update
   DEBIAN_FRONTEND=noninteractive apt-get install -y docker.io=20.10.21-0ubuntu1~18.04.3 containerd=1.6.12-0ubuntu1~18.04.1 runc=1.1.4-0ubuntu1~18.04.2
   echo '{"log-driver":"json-file","log-opts":{"max-size":"10m","max-file":"3"}}' > /etc/docker/daemon.json
   systemctl enable --now docker && systemctl restart docker
   ```

3. **加入 Swarm 并打标签**：在 CDWY1 执行 `docker swarm join-token worker`，把输出的命令（加上 `--advertise-addr 172.31.13.151`）拿到 CDWY5 执行。然后在 CDWY1 执行：

   ```bash
   docker node update --label-add lab4_role=mongo hcss-ecs-bd73
   ```

   全局服务 `lab_node-exporter` 用的是本地构建的镜像，需要先从 CDWY1 导入 CDWY5：`docker save lab3/node-exporter:20261017 | gzip` → 传输 → `gunzip | docker load`。

4. **MongoDB 7.0 镜像**（CDWY5）。服务器访问不了 Docker Hub，课程 SWR 仓库里只有 8.0。这里按官方镜像的摘要从镜像站拉取，Docker 会校验摘要，保证与官方镜像一致：

   ```bash
   D=sha256:bd7798db3c260b1f88bc4a577e1abd538aef7ae30af0b1c6f3f8e2c00285b446   # mongo:7.0 linux/amd64
   docker pull docker.m.daocloud.io/library/mongo@$D
   docker tag docker.m.daocloud.io/library/mongo@$D mongo:7.0.48
   ```

## 2 编译与打包（服务器 A：CDWY3）

```bash
source /etc/profile.d/lab3-tools.sh
export MAVEN_OPTS="-Xmx384m -XX:MaxMetaspaceSize=192m"     # CDWY3 内存紧张
cd /root/lab4/src/logdemo && mvn -B -ntp package             # 含 6 个单元测试
T=lab4-<提交号>
docker build -t xmu-javaee/logdemo-jpa:$T   logdemo-jpa
docker build -t xmu-javaee/logdemo-mongo:$T logdemo-mongo
```

预期：`BUILD SUCCESS`，两个镜像各约 360MB。

**把镜像传到 CDWY1**（走内网，约 20 秒）。先在 CDWY1 监听，再在 CDWY3 发送：

```bash
# CDWY1
nc -l 172.31.1.202 15001 | gunzip | docker load
# CDWY3
docker save xmu-javaee/logdemo-jpa:$T xmu-javaee/logdemo-mongo:$T | gzip -1 | nc -N 172.31.1.202 15001
```

两台机器上 `docker image inspect <镜像> --format '{{.Id}}'` 结果应一致。

## 3 私密配置与数据库初始化

**3.1 生成密码并创建 Docker secret（CDWY1）**：

```bash
umask 077; mkdir -p /root/.config/lab4; cd /root/.config/lab4
for f in mysql-app.pw mongo-root.pw mongo-app.pw; do [ -s $f ] || openssl rand -hex 16 > $f; done
docker secret create lab4_mongo_root_password mongo-root.pw
printf "spring.datasource.password=%s\n" "$(cat mysql-app.pw)" | docker secret create lab4_jpa_properties_v1 -
printf "spring.data.mongodb.uri=mongodb://lab4app:%s@lab4_mongo:27017/lab4_log?authSource=lab4_log\n" "$(cat mongo-app.pw)" \
  | docker secret create lab4_mongo_properties_v1 -
```

**3.2 MySQL（CDWY2）**：建库建表，再创建只能 `SELECT, INSERT` 的应用账号（密码从 CDWY1 的 `mysql-app.pw` 取，不要贴到聊天或文档里）：

```bash
CID=$(docker ps -q --filter name=lab_mysql | head -1)
docker exec -i $CID sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysql -uroot' < db/mysql/01-schema.sql
( echo "SET @lab4_app_password='<mysql-app.pw 的内容>';"; cat db/mysql/02-app-user.sql ) \
  | docker exec -i $CID sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysql -uroot'
```

**3.3 MongoDB（CDWY5，部署之后执行）**：建集合、校验规则、索引和应用账号：

```bash
CID=$(docker ps -q --filter name=lab4_mongo | head -1)
docker exec $CID sh -c 'mongosh --quiet -u root -p "$(cat /run/secrets/lab4_mongo_root_password)" --authenticationDatabase admin /import/01-init.js'
echo '<mongo-app.pw 的内容>' | docker exec -i $CID sh -c 'IFS= read -r P; LAB4_APP_PASSWORD="$P" mongosh --quiet -u root -p "$(cat /run/secrets/lab4_mongo_root_password)" --authenticationDatabase admin /import/02-app-user.js'
```

（`/import` 是 CDWY5 上 `/root/lab4/mongo/import` 的挂载点，先把 `db/mongo/*.js` 复制进去。）

## 4 部署（服务器 E：CDWY1）

```bash
mkdir -p /root/lab4/deploy && cp deploy/docker/lab4-stack.yml /root/lab4/deploy/
cat > /root/.config/lab4/deploy.env <<'EOF'
MONGO_IMAGE=mongo:7.0.48
MONGO_CACHE_GB=0.25
JPA_IMAGE=xmu-javaee/logdemo-jpa:lab4-<提交号>
MONGO_APP_IMAGE=xmu-javaee/logdemo-mongo:lab4-<提交号>
EOF
docker service scale lab_productdemoaop=0          # 测试期间暂停实验三的应用，腾出内存（测完恢复为 1）
set -a; . /root/.config/lab4/deploy.env; set +a
docker stack deploy --resolve-image never -c /root/lab4/deploy/lab4-stack.yml lab4
docker service ls --filter label=com.docker.stack.namespace=lab4
curl -s localhost:8081/actuator/health; curl -s localhost:8082/actuator/health
```

预期：三个服务 `1/1`，两个健康检查都是 `{"status":"UP"}`。CDWY5 上需先建好目录 `/root/lab4/mongo/{data,import}`。

**接口一致性检查**（CDWY3，22 项，两种实现应全部通过且逐项一致）：

```bash
python3 tools/api_check.py --base http://172.31.1.202:8081 --name jpa   > check-jpa.json
python3 tools/api_check.py --base http://172.31.1.202:8082 --name mongo > check-mongo.json
python3 tools/api_check.py --compare check-jpa.json check-mongo.json
```

## 5 预置数据并核对一致性

两台数据库服务器各自用同一个固定随机种子生成 10 万条日志并装入（各约 10 秒）：

```bash
bash deploy/scripts/seed-mysql.sh     # CDWY2：LOAD DATA INFILE
bash deploy/scripts/seed-mongo.sh     # CDWY5：mongoimport
bash deploy/scripts/digest-mysql.sh   # CDWY2：按 id 导出，计算内容摘要
bash deploy/scripts/digest-mongo.sh   # CDWY5：同上
```

预期：两边 `rows` 都是 100000，`sortedByIdSha256` 完全相同（本组为 `bbd96253…5647`）。

## 6 Prometheus（服务器 D：CDWY4）

在 `/root/prometheus/prometheus.yml` 中加入两个抓取任务，并把 CDWY5 加入 node 任务（实验四用到的配置见 `deploy/prometheus/prometheus.yml`；服务器上的文件另外保留实验三的任务，不影响本实验）。修改前先备份，修改后校验并热加载：

```bash
cp -p /root/prometheus/prometheus.yml /root/prometheus/prometheus.yml.bak-lab4-$(date +%Y%m%d-%H%M%S)
P=$(docker ps -q --filter name=lab_prometheus)
docker exec $P promtool check config /etc/prometheus/prometheus.yml
docker kill -s HUP $P
```

抓取目标用 `172.31.1.202:8081/8082`，不要用 Swarm 服务名 `lab4_logjpa:8080`（名字里有下划线，Tomcat 会对这样的 Host 头返回 400）。

## 7 压测（服务器 A：CDWY3 执行 JMeter）

**单次测试**：

```bash
source /etc/profile.d/lab3-tools.sh
cd /root/lab4/jmeter
bash run-test.sh ReadLog  172.31.1.202 8081 100 10 60 /root/lab4/results/r1/jpa-read-load-t100
bash run-test.sh WriteLog 172.31.1.202 8082 100 10 60 /root/lab4/results/r1/mongo-write-load-t100
```

参数依次为：测试计划、主机、端口（8081=MySQL 版，8082=MongoDB 版）、线程数、升压秒数、持续秒数、输出目录。JMX 文件本身不需要修改。每次测试的输出目录里有原始 JTL（`samples.jtl`）、JMeter 日志和起止时间。需要看 JMeter 自带的图表时，可用 `jmeter -g samples.jtl -o 报告目录` 另行生成（实验四不要求提交）。

**整套测试**（约 90 分钟，在能免密 SSH 到各服务器的客户端上执行）：

```bash
LAB_SSH=<你的 SSH 辅助脚本> bash deploy/scripts/run-suite.sh r1 all
```

整套流程：重启两个服务 → 两库重置为预置数据 → 各自预热 60 秒 → 负载测试 10/25/50/100 线程 → 压力测试 200/300/400 线程 → 恢复检查（10 线程）。两种实现交替执行；写测试每一档前都重置两个库，测完核对“成功请求数 = 新增行数”。

## 7b 第二阶段：主对比 3 轮、调优、过载（组员方案）

第 1 轮（10～400 线程、每档 60 秒）找到了拐点：查询在 25～50 线程附近接近吞吐峰值，写入在 100 线程附近达到峰值。第二阶段据此固定参数做正式对比，再做两项小范围调优和一项过载实验：

| 部分 | 参数 | 命令 |
| --- | --- | --- |
| 主对比 | 查询 50 线程、写入 100 线程；升压 20 秒，每个线程持续 240 秒，统计第 60～240 秒；测前用相同线程数单独预热 120 秒；3 轮 | `run-suite-v2.sh main 1 2 3` |
| 持久性对照 | MongoDB 写关注改为 w:1 + j:true，写入 100 线程，3 轮 | `run-suite-v2.sh journal 1 2 3` |
| 并发量调优 | 25/50/75/100/150 线程，其余同主对比（50、100 两档复用主对比第 1 轮） | `run-suite-v2.sh sweep` |
| 连接池调优 | 固定选出的并发量，连接池 25/50（100 复用已有结果）。并发量按规则自动选：两种实现吞吐量都不低于各自最大值 95% 的档位中，P95 最低的一档（`tools/choose_pool_threads.py`，依据写入 `results/pool/choice.txt`） | `run-suite-v2.sh pool auto`（或 `pool <查询线程> <写入线程>`） |
| 过载与恢复 | 600/800/1000 线程，升压 40 秒；JMeter 改在 CDWY4（内存更充裕）；每档后接 10 线程 60 秒恢复检查 | `run-suite-v2.sh overload` |

`run-suite-v2.sh all` 按上表顺序（主对比 → 持久性对照 → 并发量 → 过载 → 连接池）全部执行，约 6 小时。**可续跑**：已完成的测试（目录里有 `end.txt` 且 JTL 非空）自动跳过，中断后再执行同一命令即可从断点继续。脚本通过 `LAB_SSH` 指定的辅助命令登录各服务器（`$LAB_SSH cdwy3 '<命令>'`），可以在客户端运行，也可以放到服务器上运行。

**服务器端无人值守运行**（本组做法，客户端可以关机）：

1. CDWY4 上生成一把只用于这次测试的密钥：`ssh-keygen -t ed25519 -N '' -C lab4-orch-20261116 -f /root/.ssh/lab4_orch_ed25519`。
2. 把公钥加入 5 台服务器的 `/root/.ssh/authorized_keys`，行首加限制：`from="172.31.1.19",no-port-forwarding,no-X11-forwarding,no-agent-forwarding,no-pty`（只能从 CDWY4 的内网地址登录）。
3. `deploy/scripts/lab-ssh-internal.sh`、`deploy/scripts/run-all.sh` 放到 CDWY4 的 `/root/lab4/`，`run-suite-v2.sh` 放到 `/root/lab4/repo/deploy/scripts/`。
4. 启动：`nohup setsid bash /root/lab4/run-all.sh >> /root/lab4/suite-v2.log 2>&1 < /dev/null &`
5. 查看进度（CDWY4）：`tail -20 /root/lab4/suite-v2.log`，最后出现 `SUITE-DONE` 即全部完成。
6. `run-all.sh` 遇到错误会在 60 秒后从断点重试（最多 3 次）；全部完成后自动删除第 1、2 步的密钥（5 台上的那一行公钥和 CDWY4 上的密钥文件）。

切换配置用环境变量，滚动重启后在日志中核对（`logdemo-... settings: pool max-size=... writeConcern=...`）：

```bash
docker service update --env-add LOGDEMO_MONGO_JOURNAL=true lab4_logmongo     # MongoDB 写入等日志落盘
docker service update --env-add LOGDEMO_POOL_MAXSIZE=25 lab4_logjpa          # 连接池改为 25（两个服务分别设置）
```

JMeter 5.6 的“持续时间”从每个线程启动时算起：升压 20 秒、持续 240 秒时，最后一个线程约在第 260 秒结束，第 60～240 秒内所有线程都在运行。统计脚本对持续时间不少于 240 秒的测试固定统计这一区间：`python3 tools/analyze_jtl.py results/m1 --out results/统计与图表 --name m1 --fixed-window 60:240`；三轮汇总：`python3 tools/aggregate_rounds.py results/统计与图表/jtl-summary-m{1,2,3}.csv --out results/统计与图表/main-rounds`。

## 9 环境现状与注意事项

- 实验三已结束，其应用 `lab_productdemoaop` **保持 0 个副本**，不再恢复；这样 CDWY1 有足够内存同时运行实验四的两个日志服务（实验三应用与两个实验四服务同时运行时，可用内存会降到不足 100MB）。
- **不要执行 `docker stack rm lab`**：实验四用到的 MySQL（`lab_mysql`）、Prometheus（`lab_prometheus`）和各机器的 node-exporter 都属于实验三的 stack `lab`，删掉会一起消失。
- 实验四的两个服务保持运行，可直接演示：`curl -s 127.0.0.1:8081/actuator/health`、`curl -s 127.0.0.1:8082/actuator/health`。
- 在 CDWY1 上访问 Swarm ingress 端口请用 `127.0.0.1`：`localhost` 会先解析为 IPv6，ingress 不转发。
- 完全停用实验四：`docker stack rm lab4`（数据保留在 CDWY2 的 MySQL 与 CDWY5 的 `/root/lab4/mongo/data`）。
